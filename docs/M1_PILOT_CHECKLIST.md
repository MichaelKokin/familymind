# Условия закрытого пилота M1

M0 работает только с синтетическими материалами. Этот список описывает ещё необходимые инженерные и организационные работы; он не утверждает, что защита настоящих семейных данных уже реализована.

## 1. Серверное хранение и права

- [ ] PostgreSQL со схемой миграций и серверным репозиторием; локальный JSON проходит staging и проверку перед записью.
- [ ] Аутентификация, приглашения и отзыв участия; роли owner/editor/viewer. Идентификатор объекта сам по себе не даёт права доступа.
- [ ] Проверка workspace membership на каждой операции с людьми, утверждениями, источниками, файлами, заданиями, поиском и экспортом.
- [ ] Ограниченный исследователь получает grant только на конкретный кейс, с видимым сроком и отзывом.
- [ ] Журнал решений и изменений сохраняет автора и версию объекта; конфликт изменений не перезаписывает чужую работу молча.

**Проверка приёмки:** два аккаунта из разных семей не читают и не меняют чужие объекты по известным ID. Это проверяется отдельно через API, поиск, export, медиа, задания и retrieval. Третий аккаунт исследователя видит только выданный кейс. После отзыва новые запросы блокируются, включая кэши.

## 2. Оригиналы и восстановление

- [ ] Приватное object storage, серверная выдача медиа, ограниченные подписанные ссылки с документированным сроком действия.
- [ ] Upload pipeline с лимитами, проверкой MIME и содержимого, безопасным просмотром, изоляцией активного содержимого и контролем архивов.
- [ ] Оригиналы сохраняются неизменяемо; извлечённый текст, OCR и превью имеют отдельное происхождение.
- [ ] Резервная копия базы и файлов; выполнено восстановление в отдельное окружение с проверкой ссылок и хэшей.
- [ ] Экспорт проверяет права для каждого объекта и вложения, явно перечисляет исключённые файлы.
- [ ] Описаны удаление, срок хранения backup, потеря доступа и обращение при ошибке. Фактическое поведение проверено.

**Проверка приёмки:** чужой или отозванный пользователь не получает файл через старый ID/новый URL. Описан остаточный срок ранее выданной ссылки. Восстановленный проект содержит исходные документы и историю проверок.

## 3. Ограниченный семейный кейс

- [ ] Заполнен [intake](../templates/RESEARCH_INTAKE.md) вне Git: один ограниченный вопрос, известное, разрешённые документы, право на обработку, круг участников и исключения.
- [ ] Неизвестный living status обрабатывается как потенциально живой; чувствительные сведения имеют отдельное ограничение доступа.
- [ ] Согласованы хранение, срок, экспорт, отзыв и конкретные внешние обработки. Применимые правовые требования и договоры проверены для выбранной инфраструктуры.
- [ ] Настоящие данные отсутствуют в репозитории, CI, тестовых fixtures, технических логах и демонстрационном окружении.
- [ ] Назначен ответственный за поддержку и инциденты; есть способ немедленно закрыть доступ и остановить обработку.

## 4. Проверяемое исследование

- [ ] Выбран один доступный законный маршрут исследования. Ручная работа оператора допустима и обозначена как manual.
- [ ] CSV/JSON-импорт реестров проходит staging; точные headers и версия upstream проверены, ошибки не вызывают частичный импорт.
- [ ] Сохраняются фактически просмотренные коллекции, страницы/годы, запросы, исходные локаторы, покрытие и ограничения.
- [ ] Блокировка доступа и timeout не превращаются в «ничего не найдено»; повторный запуск не дублирует находки и внешние действия.
- [ ] Предложения поступают в очередь; независимость источников, однофамильцы и конфликтующие сведения проверяются человеком.
- [ ] Эксперт видит исходные материалы и может воспроизвести выбранные выводы. Недоказанные связи остаются недоказанными после принятия в рабочую версию.

Если подключается модель, до её первого вызова необходимы отдельное согласие на передачу выбранных материалов, проверенный провайдер и модель, предел расходов/шагов, остановка задания, журнал выполненных действий и защита от команд внутри документов. Секреты остаются на сервере. Наличие модели не является обязательным условием первого ручного пилота.

## 5. Решение о запуске

- [ ] Typecheck, lint, unit/integration, browser smoke и тесты авторизации проходят на релизной версии.
- [ ] Проверены отказ хранилища, конфликт версий, восстановление, отзыв grants, ограничения файлов и непрерывность export/import.
- [ ] Выбранный пользователь понимает происхождение вывода и следующий шаг; найденные ошибки исправлены или явно ограничивают scope.
- [ ] Зафиксированы участники, допустимый объём, ответственный и критерии остановки. Запуск с реальными данными разрешён отдельно от M0.

Следующая инженерная поставка — серверный репозиторий, auth и private media с тестом изоляции двух семей на синтетических данных. Только после его прохождения и ограниченного intake открывается реальный кейс.
