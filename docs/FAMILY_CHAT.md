# Семейный чат через Codex

`FamilyChat` в личном деле — живой чат через установленный Codex CLI и существующий вход ChatGPT. Отдельные API-ключи не используются. В синтетическом открытом M0 компонент предлагает открыть личное дело: демонстрационные ответы не выдаются за модельные.

## Доступ и контекст

`/api/private/chat` сначала проверяет существующую owner-сессию и точный loopback Host/Origin. GET возвращает историю; POST принимает `{question, expectedRevision, searchWeb?, searchSubjectId?}`; DELETE принимает `{turnId}`. ID дела всегда берётся из сессии. Поле caseId в JSON запрещено; query string не выбирает другое дело. Доступные заметки должны принадлежать тому же делу и owner principal. Member-сессия не даёт доступ к owner-чату даже в том же деле.

Для ответа передаются текст семейного исследования, люди и связи, источники, подписи фотографий, исходные утверждения и завершённые разборы дела, а также только доступные владельцу заметки. Бинарные фотографии не передаются; модель не должна заявлять, что видела их. Частные заметки другого участника исключает notes-runtime. Если доступ к заметке отозван или её версия изменилась, ответы с прежней заметкой в контексте скрываются при новом чтении и больше не передаются в историю модели. Уже прочитанное участником невозможно отозвать из его памяти или сделанных копий.

Один запрос ограничен 2000 символами, полный JSON-контекст — 220000 байт. Все оригинальные тексты источников и known сохраняются. Если case.excerpt точно равен research.text при совпадающем ID, вместо повторного текста передаётся явная ссылка identicalTextAt. Последние два завершённых AI-разбора передаются целиком, более ранние — с summary, вопросом и ссылками. История содержит до восьми последних доступных ответов; при нехватке места убираются самые старые. Эти количества видны в интерфейсе. Если сами материалы превышают лимит, запрос отклоняется до запуска модели. Сервер проверяет все ID цитат; названия, URL и локаторы цитат строятся из разрешённых источников, а не из придуманных моделью метаданных. Счётчик показывает ссылки контекста, включая повторные, а не число независимых свидетельств. Ответ остаётся интерпретацией модели, не изменяет дерево, доказательность или решения пользователя.

## Изолированный публичный поиск

**Текущий режим — unavailable.** Реальный проход установленного CLI `0.164.0-alpha.11.1` с `web_search="cached"` и действующими ограничениями завершился без единого события web_search. Поэтому API не объявляет поиск доступным, интерфейс показывает причину, а POST с `searchWeb=true` отклоняется до создания диалога и модельного вызова. Существующий ответ со статусом unavailable сохранён честно. Это ограничение проверенной конфигурации, а не утверждение, что Codex вообще не поддерживает веб-поиск. Ручной поиск оператором остаётся отдельным исследовательским процессом.

Подготовленный адаптер сохраняется для проверки совместимого режима: серверный список `publicSearchSubjects` содержит только research.people с явным `livingStatus=deceased` плюс явно умерший case.subject. Отсутствующий или unknown статус не выводится из старых дат или возраста. Изолированный поисковый prompt получает только выбранное имя; текст вопроса, письма, заметки, история и полный семейный контекст в него не передаются. Активация требует отдельной проверки реального вызова инструмента без ослабления приватного прохода; переключателя обхода проверки нет.

Адаптер задаёт `web_search="cached"`, документированный как поиск по индексу OpenAI: [официальная документация](https://learn.chatgpt.com/docs/web-search#configure-local-web-search). Поддержка настройки не означает доступность инструмента в выбранной конфигурации. Cached-поиск не гарантирует текущую страницу или доступ к оригиналу. Полученные ссылки могут показываться только как **непроверенные поисковые зацепки**, отдельно от цитат семейного дела. Реальный статус `performed` требует события web_search от CLI; без него предложенные ссылки не принимаются. Приложение не заявляет, что само загрузило и проверило оригинал по новой ссылке.

В поисковом проходе допустимы только события web_search, максимум три tool item и шесть зарегистрированных запросов. Статус performed требует завершённого tool item. Основной проход ответа отключает веб-поиск и инструменты. Перед каждым модельным проходом конфигурация проверяется без запуска модели: CLI перечисляет MCP с теми же отключёнными apps/plugins/features, затем каждому серверу задаётся enabled=false и безопасный dummy transport того же типа. Второе чтение обязано показать ноль включённых серверов; неизвестный формат или тип отклоняется. Секреты и реальные адреса из конфигурации не копируются в аргументы процесса. Полные выключенные таблицы остаются валидными при exec --ignore-user-config. Пустой override mcp_servers={} не используется как гарантия: он не очищает объединяемые настройки.

Далее проверяется фактическое отключение feature gates оболочки, приложений, плагинов, браузера, компьютера и памяти. В этой версии CLI unified_exec остаётся выбором backend, а доступность команд отключает shell_tool=false; этот gate проверяется отдельно. Официальное описание shell_tool: [схема конфигурации агента](https://learn.chatgpt.com/docs/agent-configuration/subagents#custom-agent-file-schema). Неожиданное tool-событие дополнительно завершает запуск ошибкой; этот контроль не заменяет проверки до передачи prompt. Диагностический item:error не считается вызовом инструмента: установленный CLI, например, так предупреждает об отключённом Code Mode. При этом top-level error, turn.failed, ненулевой exit code, отсутствие turn.completed или неверный результат остаются ошибками. Ошибки preflight различаются безопасными кодами этапа без сохранения конфигурации/секретов. Никакие письма или запросы архивам не отправляются.

## Сохранение и остановка

История хранится вне checkout в `chat/<caseId>.json`; предыдущие ревизии — в `chat-backups/<caseId>/`. Права каталогов 0700, файлов 0600. Используются существующие атомарная запись и межпроцессный lock. Лимит истории — 100 вопросов; в одном деле одновременно выполняется только один ответ. Терминальные ответы не перезаписываются; завершение после отмены не возвращает статус completed.

Поиск ограничен 90 секундами, ответ — 180. Остановка сохраняет cancelled и прерывает фактический процесс CLI; другой серверный worker замечает отмену при проверке файла в пределах секунды. После SIGTERM предусмотрен SIGKILL через пять секунд. Незавершённый запуск старше шести минут помечается interrupted. Временные схемы и ответы удаляются после завершения; приватный prompt не записывается приложением на диск и не помещается в диагностические сообщения. CLI запускается с ephemeral; обработка всё равно происходит через сервис Codex, а не полностью локально.

## Проверка

`npx vitest run tests/family-chat.test.ts` — 29 synthetic-only проверок: полный разрешённый контекст и отсутствие image bytes, разделение поискового и приватного проходов, чужие ID цитат, лимиты, изменение/потеря доступа к заметке, историю/ревизии/одновременность, отмену настоящего fake-процесса, отсутствие API fallback, отказ небезопасной конфигурации до prompt, безопасные выключенные MCP transports, ложное завершение, отсутствие события поиска, явный deceased scope, чужой case/principal и CSRF. Отдельные регрессии отличают диагностический item:error с валидным финалом от turn.failed или ненулевого exit code. Локальный preflight проверен с установленным CLI отдельно, без модельного вызова и без вывода конфигурационных секретов. Настоящий CLI также успешно вернул валидный ответ на маленький синтетический prompt после исправления обработки диагностики; это не проверка истинности семейного ответа.

`e2e/family-chat.spec.ts` добавляет два browser-сценария через production build и отдельный synthetic-root/порт3001: ответ/цитата/перезагрузка/CSRF; честная недоступность внешнего поиска с отказом API до запуска и отмена ответа. Fake executable не делает сетевых или модельных вызовов и отказывается работать вне папки тестов. Запуск — `node e2e/run-private.mjs family-chat.spec.ts` после сборки; общий private suite включает этот файл.

Реальные модельные запросы выполняются отдельно оператором с разрешёнными материалами. Успешные unit-тесты с fake CLI не доказывают доступность ChatGPT-квоты или конкретных результатов поиска. Этот owner-only чат не является многопользовательским M1.

Финальная приёмка владельца процесса 6 ноября: на production-сервере получены два настоящих ответа по разрешённым семейным материалам, ссылки и оговорки просмотрены, история прочитана после перезагрузки. Внешний поиск не подтвердился и отключён в текущей поставке. Общий private browser suite — 9/9; настоящие персональные материалы не использовались в автоматических тестах.
