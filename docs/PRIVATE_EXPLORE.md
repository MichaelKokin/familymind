# Приватное семейное пространство

`/case/explore` — интерактивный, доступный только после открытия дела обзор подготовленного исследования. Слева — галерея оригинальных изображений и следующие проверки, в центре — карта людей и источников либо доступный список, справа — история выбранного человека, фотографии и основания связей. Поиск и выбор ветви работают локально. Нажатие на изображение, источник или связь показывает происхождение и исходный статус.

Карта — **manual / generated snapshot**. Она не редактирует семейное дерево и не превращает гипотезы в подтверждённые факты. Позиции вычисляются из явных родительских связей; они не сохраняются. Исследовательские действия и решения остаются в `/case`, подробный текст — в защищённом отчёте. Отдельные вкладка FamilyChat и заметки MemberNotes используют собственные серверные операции; их поведение не считается частью статического среза.

## Контракт оператора

Вне checkout подготовить `research/<ID дела>.json` относительно `FAMILYMIND_PRIVATE_ROOT`, каталог с правами0700, файл0600. ID берётся только из авторизованного дела. Максимум20MiB на JSON. Контракт строго проверяет [research-model.ts](../src/private-case/research-model.ts):

```ts
{
  schemaVersion: 1,
  title: string,
  owner: { name: string, subtitle?: string, personId?: string },
  summary: string,
  people: [{ id, name, dates, relation, biography, branch, status,
    sourceIds: string[], photoIds: string[], generation: number,
    birthDate?: string, birthPlace?: string, deathDate?: string,
    deathPlace?: string, residencePlaces?: string[],
    placeFacts?: [{ kind: 'birth' | 'residence' | 'death' | 'evacuation',
      place: string, dateText?: string, sourceIds: string[], status: string }] }],
  relationships: [{ id, from, to, label, status, sourceIds: string[],
    kind?: 'parent_child' | 'partner' | 'other',
    parentRole?: 'father' | 'mother' | 'parent' }],
  sources: [{ id, title, url, locator, kind, text?: string }],
  photos: [{ id, title, caption, personIds: string[], sourceId, dataUrl }],
  questions: [{ title, why, nextStep }]
}
```

Все неуточнённые поля — строки. `generation` сохранён для совместимости (целое от0 до12), но больше не определяет расположение и родство. Корень задаёт `owner.personId`; он выбран при открытии. Отсутствие корня не заменяется догадкой по имени или порядку карточек: люди остаются в списке. У `parent_child` направление строго **`from` = родитель, `to` = ребёнок**. `parentRole` допустим только для этого вида связи. `partner`, `other` и старые нетипизированные записи сохраняются в инспекторе, но не создают предков на карте. Текст `status` не меняется при выборе карточки или построении пути.

## Решение о расположении предков

Обход идёт от владельца вверх только по `parent_child`. Отцовская ветвь целиком слева, материнская целиком справа; роль `parent` остаётся отдельной неуточнённой линией. Все люди одного уровня находятся на одной горизонтали, без переноса в следующий ряд. Поколения уплотняются отдельно наружу от разделителя ветвей: широкая дальняя ветвь не отодвигает непосредственных родителей от владельца. Начальный масштаб показывает владельца и его родителей; «Ко мне» возвращает этот вид, «Все поколения» показывает дерево целиком.

Путь «Вы → Мать → Мать» строится из конкретных рёбер. Супружество, фамилия, подпись `relation`, старое поле `generation` или соседство карточек не создают родство. Для предка, встречающегося по двум путям, создаются две визуальные позиции **одного personId** с пометкой; исходные сущности не дублируются. Циклические рёбра не рисуются и показывают предупреждение. Обход ограничен12 уровнями и1000 позициями; при отсечении видна пометка, все люди остаются в списке.

Неизвестные даты и места обозначаются явно. Текст дат не нормализуется и не выводится из общей строки `dates`. Предпочтительный формат географии — `placeFacts`, чтобы место, период, статус и источники оставались вместе; простые поля используются как совместимый fallback. Ссылки `placeFacts.sourceIds` проверяются в пределах того же набора.

В `photos` не более30 исходных JPEG/PNG/WebP, каждый не более8MiB в декодированном виде. `dataUrl` содержит встроенный base64; внешние изображения, SVG, файловые пути и HTML запрещены. Изображения показываются без обрезки; приложение не генерирует лица и не удаляет водяные знаки. У каждого изображения обязателен существующий источник. URL источника — HTTP(S) без credentials либо пустая строка. Источники, изображения и люди должны иметь уникальные ID; все ссылки проверяются.

## Граница доступа

`GET /api/private/research` выполняет `loadOwnedCase` до чтения. Путь выбирается сервером из session-bound ID; query-параметры его не меняют. Каталог и файл не могут быть symlink, файл должен быть обычным; `O_NOFOLLOW`, `O_NONBLOCK` и ограниченное чтение защищают от подмены ссылкой, FIFO и роста сверх лимита. Проверяются MIME-префикс, сигнатура и каноничность base64. Ответ не кешируется. Без сеанса —401, при отсутствии или некорректном файле —404 без раскрытия локальных путей.

Данные и встроенные изображения находятся в памяти открытой страницы. Это локальный режим владельца ОС, не многопользовательский media service; шифрование, tenant isolation и автоматическая синхронизация с исследовательским делом не заявлены.

## Проверка

`tests/private-research.test.ts` проверяет авторизацию, выбор только собственного дела, traversal, symlink, oversize, изображение и целостность ссылок. `tests/ancestry-layout.test.ts` проверяет материнскую бабушку, направленность рёбер, независимость от порядка/подписей/номеров поколений, широкие ряды, повторного предка, циклы и ссылки географических сведений. Production E2E в `e2e/private-case.spec.ts` использует отдельный synthetic root: открытие из дела, выбор человека, источник, галерею, reload и mobile390px; отдельный сценарий проверяет переход от владельца к материнской бабушке и конкретного ребёнка её связи. Реальные имена и фотографии в fixtures не используются.

## Редактируемое личное пространство · 7 ноября 2026

Поверх неизменяемого среза работает редактор: владелец добавляет близких с явно выбранной связью, материалы с оригиналом и происхождением, перетаскивает карточки и возвращается к сохранённой композиции. Срез `research/<ID>.json` при этом не изменяется и остаётся оригиналом оператора; пространство хранит только собственные записи и ссылки на `personId` среза.

### Хранение

| Путь (вне checkout, относительно `FAMILYMIND_PRIVATE_ROOT`) | Содержимое |
|---|---|
| `space/<ID дела>.json` | Пространство: люди, связи, материалы (метаданные), композиция, пропущенные подсказки, журнал. Права 0600, атомарная запись, лимит 4 MiB. |
| `space-media/<ID дела>/<ID материала>.bin` | Оригиналы материалов байт в байт. Один файл на материал, записывается один раз; подпись, размер и SHA-256 проверяются при записи и при каждом чтении. |
| `space-backups/<ID дела>/<ревизия>.json` | Полная предыдущая ревизия перед каждой перезаписью. |

До первой записи пространство существует виртуально (ревизия 0): `GET /api/private/space` ничего не создаёт. Первая успешная мутация записывает файл с журнальной записью `migrated` и контрольной суммой среза в `base.snapshotDigest`. Если срез позже заменён, интерфейс показывает предупреждение; ссылки на исчезнувших людей не рисуются, но сохраняются.

### Модель

- **Человек** (`people[]`): `id`, `name`, исходный текст даты, `livingStatus` (`living`/`deceased`/`unknown`), заметка, `createdAt`/`updatedAt`/`removedAt`. Полей поколения и ветви нет — они не выводятся.
- **Связь** (`relationships[]`): `from`, `to`, `kind` (`parent_child` строго родитель → ребёнок с обязательным `parentRole`; `partner`; `other` с обязательной подписью), `label`, `rationale`, `evidenceStatus` только `hypothesis` или `unresolved`, `origin: owner_statement`. Дубликаты той же пары и вида, включая связи среза, отклоняются; одинаковые имена людей не объединяются.
- **Материал** (`materials[]`): `kind` (`photo`/`document`/`note`/`link`), название, текст, URL (только http/https без учётных данных), происхождение, дата как текст, `personIds[]`, `original` (`name`, `mime`, `size`, `sha256`) или `null`. Заметке нужен текст, ссылке — адрес; у заметок и ссылок оригинала нет.
- **Композиция** (`layout.positions`): ручные координаты по ID узла (`root:<person>`, `ancestor:<связи…>`, `person:<id>`, `material:<id>`). Карточки без записи размещаются автоматически и не сдвигают ручные.
- **Журнал** (`journal[]`): append-only записи `migrated`, `add_*`, `update_*`, `remove_*`, `restore_*`, `reset_layout`, `import`. Перемещения карточек в журнал не пишутся.

Инварианты при каждом сохранении: ревизия совпадает (CAS, иначе 409); записи не исчезают — убирание ставит `removedAt`, возвращение снимает; `createdAt`, участники связи и уже сохранённый `original` неизменяемы; `base` и префикс журнала неизменяемы. Карточку центра убрать нельзя. Срез не редактируется (`SNAPSHOT_READ_ONLY`).

### API (только owner-сессия дела; Host, Origin и cookie как у остальных private-маршрутов)

| Маршрут | Назначение |
|---|---|
| `GET /api/private/space` | Срез (если есть), пространство, контрольная сумма среза и предупреждения. |
| `POST /api/private/space/mutate` | `{expectedRevision, action}`: `add_person` (с необязательной связью к существующему человеку и ролью), `update_person`, `remove_person`/`restore_person`, `add_relationship`/`update_relationship`/`remove_relationship`/`restore_relationship`, `update_material`/`remove_material`/`restore_material`, `layout`, `reset_layout`, `guide_dismiss`/`guide_reset`. Тело до 64 KiB. |
| `POST /api/private/space/material` | `{expectedRevision, material, file?}`; файл — data URL PNG/JPEG/WebP/PDF/TXT до 5 MiB, общий объём оригиналов дела до 40 MiB. Сначала записывается оригинал, затем метаданные; при отказе метаданных только что созданный файл удаляется. |
| `GET /api/private/space/media?id=` | Оригинал материала этого дела. Изображения `inline`, остальное `attachment`; `no-store`, `nosniff`, CSP `default-src 'none'; sandbox`. ID из другого дела — 404. |
| `POST /api/private/space/export` | Пакет `family-mind-space` v1: пространство, контрольная сумма среза и оригиналы base64. Заметки участников и срез не включаются. |
| `POST /api/private/space/import` | `{expectedRevision, bundle}` до 64 MiB. Только то же дело. Проверяются формат, ссылки на людей, каждый файл (подпись, размер, SHA-256) **до** любой записи; повреждённая копия отклоняется целиком. Записи, отсутствующие в копии, помечаются убранными, а не удаляются; журнал дополняется записью `import`. |

Коды ошибок: `STALE_REVISION` (409), `PERSON_NOT_FOUND`/`MATERIAL_NOT_FOUND`/`RELATIONSHIP_NOT_FOUND`/`MATERIAL_FILE_MISSING` (404), `ORIGIN_FORBIDDEN`/`HOST_FORBIDDEN` (403), остальные — 400 без раскрытия путей и содержимого.

### Автоматическая раскладка и ручная композиция

Предки — прежний алгоритм (`ancestry-layout.ts`) по объединённым связям среза и пространства: отцовская ветвь слева, материнская справа, поколение на одной горизонтали. Потомки владельца — рядами ниже; партнёры и «другие связи» — рядом с человеком; люди без связи с размещёнными — колонкой справа. Материалы — с внешней стороны ветви рядом с первым связанным человеком, без связи — колонкой слева. Сначала фиксируются карточки с ручными позициями, затем автоматические обходят занятые места; добавление карточек не двигает ручные. «Вернуть авторазмещение» удаляет ручную позицию конкретной карточки. Если человек становится предком (появляется цепочка к владельцу), его узел меняет ID и возвращается к автоматическому положению.

### Восстановление

Срез не изменяется, поэтому прежний read-only вид доступен всегда. Предыдущие ревизии пространства лежат в `space-backups/<ID>/`; восстановить состояние можно импортом ранее сделанного экспорта (записи вне копии станут убранными, оригиналы сохранятся) либо оператором — копированием нужной резервной ревизии на место `space/<ID>.json` при остановленном сервере. Файлы оригиналов приложение никогда не удаляет.

### Проводник

`space-guide.ts` предлагает ровно один следующий шаг по сохранённым данным и выбранной карточке: назначить центр, добавить первого близкого, добавить родителя выбранному человеку, добавить материал, связать материал с человеком, спросить помощника (вопрос подставляется в чат). Пропуск сохраняется в `guide.dismissed`; «Показать пропущенные снова» очищает список. Подсказки не выполняют и не имитируют поиск.

### Проверка

`npx vitest run tests/private-space.test.ts tests/space-layout.test.ts` — редьюсер, хранилище, API (401/403/404/409, scope дела, оригиналы, экспорт/импорт, отказ без записи), раскладка (без пересечений, ручные позиции, новые карточки), проводник. `e2e/private-space.spec.ts` в составе `npm run test:private`: добавление родителя и фотографии через формы, перетаскивание, reload, экспорт, убирание, отказ повреждённого импорта, импорт, 401/403/409, пропуск подсказки, однофамилец и ввод на 390 px. Реальные данные в тестах не используются.

## Вторая поставка 7 ноября 2026 · канвас по продуктовой основе и ручной маршрут находки

### Три постоянных элемента

Экран `/case/explore` собран по разделу 8 продуктовой основы: **канвас** на всю ширину, **компактный помощник** в левом нижнем углу (одна подсказка, состояние поиска, чат Codex по кнопке «Спросить Codex») и **панель выбранного объекта** справа (обзор пространства, человек, материал, кандидат находки или вопрос поиска). Одна первичная кнопка «＋ Добавить · для <человек>» открывает меню: родителя, партнёра, ребёнка, другую связь, связать двух людей, фотографию, документ, ссылку, заметку, зацепку для поиска. Второстепенные действия (экспорт, импорт, убранные карточки) — в меню «Ещё». При пустом пространстве показывается подсказка-выноска у карточки «Я».

Визуальные токены взяты из основы как гипотеза: тёплый светлый фон, графитовый текст, приглушённый зелёный акцент, антиква только для имён и заголовков историй, статусы — читаемым текстом. Карточки людей показывают фотографию крупнее, материалы — полосу изображения, кандидаты находок — отдельный янтарный тип карточки с источником и объяснением. На телефоне тулбар, кнопка добавления и помощник становятся обычными блоками под канвасом; горизонтального переполнения нет на 390 px.

### Зацепки, кандидаты и находки

Автоматический внешний поиск недоступен (установленный Codex не подтвердил `web_search`), поэтому маршрут реализован честно как **операторский ручной**: приложение фиксирует вопрос, что проверено и исход, но ничего не ищет само и не имитирует прогресс.

| Сущность | Поля | Правила |
|---|---|---|
| **Зацепка** (`leads[]`) | `personId` или `null`, `question`, `placeText`, `periodText`, `mode: "manual"`, `status`, `coverage`, `missingDetail`, `nextQuestion` | Статусы: `open` → `candidate` (выставляется только записью кандидата) → `done` при принятии; `nothing_found` требует текста «что проверено»; `needs_detail` требует «какая деталь поможет»; `cancelled` закрывает вопрос без записи кандидатов. |
| **Кандидат находки** (`finds[]`) | `leadId` или `null`, `personIds`, `title`, `source` (`title`, `url`, `locator`, `excerpt`, `kind`, `dateText`), `why`, `novelty` (`new`/`known`), `performedBy: "operator_manual"`, `status`, `decisionReason`, `decidedAt`, `materialId` | Нужны объяснение совпадения и хотя бы адрес, локатор или выдержка. Статусы `candidate` → `accepted` / `contested` / `rejected` с обязательной причиной; принятое решение, источник и `leadId` неизменяемы, в том числе при импорте. |

Принятие создаёт материал с `origin: "external_find"` и `findId`: ссылка (если есть URL) или документ, происхождение собирается из названия источника, локатора и вида; материал размещается рядом с выбранными людьми. Карточка кандидата исчезает с канваса, но остаётся в истории вопроса и в панели человека. Оспаривание (например, однофамилец) и отклонение сохраняют причину и возвращают вопрос в `open`, пока у него нет других кандидатов. «Уже знакомая страница» и «новое для меня» учитываются отдельно (`novelty`). Принятие владельцем не меняет доказательный статус: в интерфейсе это повторяется текстом.

К материалу без оригинала (в том числе принятой находке) можно позже приложить файл: `POST /api/private/space/material` с `{expectedRevision, materialId, file}`; повторная замена отклоняется (`ORIGINAL_ALREADY_SET`, 409).

Новые действия `POST /api/private/space/mutate`: `add_lead`, `update_lead` (патч полей и статус, кроме производного `candidate`), `add_find`, `decide_find` (`decision`, `reason`, для `accepted` — `personIds` и `nextQuestion`). Журнал получает `add_lead`, `update_lead`, `add_find`, `decide_find`, `attach_original`. Экспорт/импорт переносят зацепки и находки; записи, отсутствующие в копии, помечаются убранными.

### Проводник и помощник

Правила `space-guide.ts` расширены: ожидающий кандидат предлагается к проверке первым; вопрос со статусом «нужно уточнение» просит деталь; человеку с материалом или родителем, но без вопроса, предлагается сформулировать зацепку; после первого материала — первую зацепку для владельца. Чат Codex получает записи пространства как `space` (люди, связи-гипотезы, материалы без байтов, вопросы и кандидаты) и может ссылаться на материалы и кандидатов как `space:<id>`; нажатие на такую ссылку открывает карточку. Промпт прямо указывает, что это утверждения владельца и операторские находки, а не проверенные источники.

### Проверка

`tests/private-space-finds.test.ts` — редьюсер зацепок/кандидатов, размещение кандидатов, правила проводника, приложение оригинала через API, неизменяемость решений при импорте, контекст чата. `e2e/private-space.spec.ts` — сценарий «зацепка → кандидат → оспорить (однофамилец) → ничего не найдено с покрытием → новый кандидат → принять и разместить → приложить оригинал → перезагрузка», плюс прежние сценарии редактора и телефона. Реальные данные не используются.
