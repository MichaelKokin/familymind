# Локальное исследовательское дело

Маршрут `/case` — отдельный серверный режим для одного ограниченного исследования. Он хранит дело вне репозитория, требует доступ к конкретному делу и умеет передать выбранные фрагменты в установленный Codex. Маршрут `/` остаётся синтетическим M0 с IndexedDB; настоящие сведения туда не импортируются.

Это локальный режим для владельца компьютера, **не многопользовательский M1**. Ограниченные локальные кабинеты и приглашения дают участникам только личные/семейные заметки, как описано в [MEMBER_NOTES.md](MEMBER_NOTES.md). Исследовательское дело, граф, медиа и чат остаются доступными владельцу. Облачного развёртывания, полноценных семейных ролей, приватного media service и публичных ссылок нет. Разрешение на конкретный реальный кейс не распространяется на другие семьи, документы или внешние действия.

## Запуск и доступ

Обычные `npm run dev` либо `npm run build` → `npm start` запускают приложение на `http://127.0.0.1:3000`. Одновременно порт занимает только один сервер. Не заменяйте адрес на `localhost`: API проверяет точный loopback origin и Host.

Первоначальное дело и одноразовую ссылку создаёт оператор через `PrivateCaseStore` и `LocalCaseAccess`. Интерфейс не создаёт произвольные реальные дела. Ссылка имеет форму `/case#token=<одноразовый-токен>`; секрет удаляется из адресной строки до загрузки данных. Его не следует сохранять в Git, документации или технических отчётах.

Для уже созданного дела при работающем сервере выполните `npm run case:open`. Если дел несколько — `npm run case:open -- <ID>`. Команда открывает браузер с новой одноразовой ссылкой и не печатает ключ в консоль; при отсутствии дела или сервера сообщает ошибку.

На macOS можно дважды нажать `Open Family Mind.command` в корне проекта или выполнить `npm run case:launch`. Запуск проверяет PID, рабочую папку Next.js и loopback-адрес слушателя на порту 3000. Он переиспользует сервер этого checkout; при свободном порту запускает существующую production-сборку в фоне и ждёт готовности. Занятый чужим процессом порт и смена PID приводят к отказу без остановки процессов и без выдачи ссылки. Сборка автоматически не меняется: если `.next/BUILD_ID` отсутствует, сначала нужен `npm run build`. Диагностика запуска — `.local/runtime/server.log`, PID — `.local/runtime/server.json`; оба пути исключены из Git.

Двойной щелчок ищет Node.js в обычном PATH, Homebrew и затем загружает установленный `~/.nvm/nvm.sh`, если Node не найден. При нестандартной установке откройте Терминал, где работают Node.js 20.19+ и npm, перейдите в папку проекта и выполните `npm run case:launch`. Для нескольких дел передайте ID после `--`; запуск не выбирает произвольное дело. Это локальная команда владельца компьютера, а не публичный HTTP-метод восстановления доступа.

Если `/case/explore` показывает закрытый доступ, повторный запуск команды выдаст новую одноразовую ссылку. Она открывается в браузере по умолчанию и после успешного обмена переводит на `/case/explore`; `view=explore` — единственный разрешённый дополнительный переход, произвольных redirect URL нет. Продолжайте в этой вкладке. Обычная ссылка на страницу и старый использованный токен не открывают новый сеанс; другой браузер может иметь отдельные cookies. Вход владельца удаляет прежнюю cookie участника, чтобы устаревший кабинет не блокировал заметки и чат. Обычные запросы с невалидной cookie участника по-прежнему получают отказ.

`npm run case:audit -- <ID>` сохраняет четыре CSV-реестра в приватную папку `evidence/<ID>/<revision>/` и запускает закреплённый upstream `audit_evidence.py`. Полный `audit.json` остаётся там же; в консоль попадают только количества и число ошибок/предупреждений. Это проверка структуры, не доказательство исторической истинности. Существующие CSV с отличающимся содержимым команда не перезаписывает.

Bootstrap действует по умолчанию пять минут и обменивается только один раз. Сервер выдаёт привязанную к одному делу cookie `fm_private_session`: HttpOnly, SameSite=Strict, путь `/api/private`, срок восемь часов. Кнопка «Закрыть сеанс» отзывает серверную сессию; для повторного открытия нужна новая ссылка. Это доступ по владению секретом, а не подтверждённая личность члена семьи.

Все private API проверяют сессию, Host и origin; изменяющие запросы требуют правильный Origin. Ответы имеют `Cache-Control: private, no-store`. URL источника сохраняется как metadata: приложение не загружает его автоматически. Внешнюю страницу можно открыть вручную из карточки.

## Где находятся данные

По умолчанию: `~/Library/Application Support/FamilyMind/private-cases/`. Серверный `FAMILYMIND_PRIVATE_ROOT` позволяет выбрать другую абсолютную папку вне checkout. `FAMILYMIND_ORIGIN` задаёт точный `http://127.0.0.1:<порт>` для проверки запросов; это настройка оператора, не переключатель в браузере.

- `cases/` — валидированные JSON-дела: исходные сведения, источники, вопросы, запуски и решения.
- `backups/` — предыдущие полные ревизии перед заменой текущего файла.
- `auth/` — хэши bootstrap/session секретов и сроки. Сами секреты в этом реестре не сохраняются.
- `jobs/` — временная схема и результат одного CLI-запуска; рабочая папка удаляется после завершения или ошибки.

Каталоги имеют права 0700, файлы — 0600. Запись выполняется через временный файл, `fsync` и атомарное переименование; ревизия и lock защищают от одновременной перезаписи. Источники и журнал решений не затираются импортом. **JSON не зашифрован**: владелец учётной записи ОС и процессы с её правами могут его прочитать. Копии на том же диске не заменяют отдельный backup и проверенное восстановление после потери компьютера.

Экспорт — обычный незашифрованный JSON в папку загрузок браузера. Хранить его вне Git. Импорт допускается только в то же дело и сохраняет уже существующие оригиналы источников, решения и завершённые запуски; импорт старой копии не служит откатом истории. Пока исследование активно, импорт заблокирован.

## Что делает исследование

Пользователь задаёт один вопрос и выбирает источники. Сервер передаёт в Codex данные об исследуемом человеке, вопрос, выбранные фрагменты и исходные утверждения, для которых все ссылки входят в выбранный набор. Невыбранные материалы не должны попадать в этот запуск.

Адаптер вызывает установленный `codex` через текущую авторизацию ChatGPT. Отдельный API-ключ не нужен; API-key fallback отключён. Действуют доступная квота и ограничения существующего аккаунта. Переданные фрагменты обрабатываются Codex: это не полностью офлайн-вычисление.

Перед запуском адаптер проверяет `codex --no-daemon login status` и допускает только вход через ChatGPT. API-key login, отсутствие CLI или истёкший доступ дают ошибку; приложение не подменяет её демонстрационным ответом.

CLI запускается с read-only sandbox, без пользовательских конфигураций и правил, с отключёнными web search, shell, apps, plugins, memories и прочими инструментами. Тексты источников передаются как недоверенные данные. Если CLI всё же сообщает использование инструмента, адаптер отказывает в результате. Запуск ограничен по времени и размеру ответа; схема JSON и ссылки на источники проверяются до сохранения.

Результат состоит из разбора материалов, наблюдений с source IDs, пробелов, следующих проверок и предложений. Предложения имеют доказательный статус только `hypothesis` или `unresolved`. Решение человека записывается отдельно; принятие не превращает семейное дерево или совпадение имени в доказанное родство. Исходные утверждения дерева остаются `tree_assertion`.

`completed` означает, что получен и сохранён валидный результат анализа переданных материалов. **Это не результат поиска во внешних архивах.** В текущем адаптере нет сканирования сайтов, OCR, автоматической отправки запросов, оплаты, изменения чужого дерева или установленного FamilySearch MCP. Причина ошибки отображается отдельно; перезапуск не выдаётся за завершённое исследование.

## Методика Дениса Ширяева

В `vendor/ex-ussr-kinship-research/` сохранён ограниченный набор файлов commit `84b0eda770b002464e84658a8f63046a4bb94e95`, version 1.34.0: `SKILL.md`, протокол доказательств, стратегия источников, `audit_evidence.py`, его модуль `research_common.py`, четыре CSV-шаблона реестров и MIT license. `PROVENANCE.json` содержит SHA-256 и размеры; локальная сверка **10/10** файлов с manifest выполнена.

`src/private-case/methodology.ts` содержит ограниченную адаптацию правил доказательств для промпта. `buildEvidenceRegisters` формирует четыре реестра с точными заголовками upstream: человек, источники, утверждения и связи. Текст предложений не превращается в генеалогические рёбра; неизвестная независимость остаётся пустой, утверждения дерева экспортируются как гипотезы. Точный исходный текст остаётся в JSON; CSV дополнительно защищает ячейки от интерпретации формул в табличных программах.

Кнопка «Экспорт реестров» скачивает JSON-пакет с этими четырьмя CSV, версией методики и ограничениями. Это отдельный формат для структурного аудита; копия всего дела скачивается через «Экспорт дела».

Тест адаптера вызывает `audit_evidence.py` только на временных синтетических CSV. Это структурная проверка, не доказательство генеалогической истины. Файлов семейного дела в vendor нет. Полное автономное исполнение upstream-скилла и архивные подключения этим не заявляются. MIT notice сохранён. Права на архивные материалы не следуют из лицензии кода.

## Изолированная проверка без настоящих данных и модельных вызовов

После production-сборки:

```bash
npm run build
node e2e/run-private.mjs --reporter=line
```

Wrapper создаёт собственную временную папку вне checkout, запускает отдельный production-сервер на `127.0.0.1:3001` и принудительно указывает синтетический CLI fixture вместо настоящего Codex. Он не переиспользует живой сервер и не открывает обычный private root. После завершения удаляется только созданная этой командой тестовая папка. На порту 3001 не должен работать другой процесс.

Проверяются одноразовый доступ, cookie, отказ без сессии и при чужом origin, отзыв сессии, привязка к делу, добавление источника, ограниченный запуск через тестовый процесс, review без повышения доказательности, reload, JSON export/import, stale revision и чужой source ID. Это проверка серверного и браузерного процесса; она не оценивает качество настоящей модели или фактический архивный поиск. Фактический итог команд записывается в [статусе реализации](IMPLEMENTATION_STATUS.md).
