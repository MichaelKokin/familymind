# Личный кабинет и заметки участников

Рабочий локальный сценарий: `/case/members`. Владелец входит через существующую ссылку дела. Кабинет показывает его собственные личные заметки и семейные заметки участников. В семейном пространстве тот же компонент можно открыть для выбранного `personId`.

## Доступ

- «Только мне»: сервер отдаёт заметку только её автору. Владелец дела не получает чужие личные заметки ни в списке, ни по прямому ID, ни в контексте чата.
- «Семье»: заметка доступна активным участникам того же дела. Это не публикация в интернете.
- Изменять и удалять запись может только автор. При конкурирующем редактировании проверяется ревизия; устаревшая запись не затирает новую.
- Для недоступной и несуществующей заметки используется одинаковый ответ 404. Автор и дело определяются из серверной сессии, а не из полей формы.

Владелец создаёт приглашение по кнопке. Ссылка локальная, действует 10 минут и используется один раз. Ничего не отправляется автоматически. Получателю нужен отдельный профиль или приватное окно на этом компьютере. Открытие приглашения в окне владельца переключает браузер на ограниченный сеанс участника, очищая owner-cookie. Новая ссылка для уже существующего участника сохраняет его `memberId` и личные заметки, заменяя прежнюю неиспользованную ссылку.

Сеанс участника действует 8 часов; токен хранится в HttpOnly/SameSite=Strict cookie. На диске сохранён только SHA-256 токена. Сервер проверяет loopback Host и Origin и не принимает member-cookie как доступ владельца. Отзыв членства блокирует каждый последующий запрос, включая запросы с ранее полученным principal. Уже показанные или скопированные материалы отозвать невозможно.

## Границы поставки

Это кабинет заметок. Приглашение предоставляет имена людей этого дела, личные записи самого участника и семейные записи. Оно **не даёт** доступа к owner-only исследованию, письмам, фотографиям, экспорту дела или AI-чату. Участники не могут приглашать других участников. Интернет-регистрации, паролей, email-рассылки, самостоятельного дерева участника и удалённого семейного сервиса пока нет.

Заметки хранятся отдельно в `member-notes/<caseId>.json`, с правами каталога 0700 и файла 0600, вне Git. Данные не шифруются от владельца ОС. В обычный owner-only JSON-экспорт дела заметки автоматически не добавляются: такой экспорт не должен обходить их авторскую приватность. В кабинете работает отдельный JSON-экспорт только доступных текущему участнику заметок: его личных и семейных записей. Сервер повторно проверяет доступ и включает только относящиеся к ним имена и авторов. Экспорт не зашифрован. Обратный импорт пока не поддерживается: необходим явный mapping авторства, чтобы не создавать чужие приватные заметки из произвольного файла. Локальные лимиты: 50 записей участников и 1000 заметок на дело, 10 000 символов в заметке, общий файл до 4 MiB.

`listAccessibleNotes(request)` — единственная точка получения заметок для чата. Она заново проверяет сессию и фильтрует авторскую приватность. Контекст чата должен сверять `caseId` и owner identity с авторизованным делом и не читать raw-файлы заметок. Текст заметки остаётся пользовательским свидетельством, не доказанным генеалогическим фактом.

## Проверки

Выполнены `npx vitest run tests/member-notes.test.ts` — **8/8**, scoped ESLint и TypeScript. Тесты используют только временные синтетические данные: три автора одной семьи и другую семью; прямые ID; запрет изменения чужой записи; отзыв доступа; конкурентные правки; ограниченные capability; повторное приглашение с сохранением авторства; отсутствие raw-токенов; срок сеанса; CSRF и Host.

Добавлен браузерный сценарий `e2e/member-notes.spec.ts`, входящий в `npm run test:private`: две независимые браузерные сессии, запись/reload, приватная и семейная видимость, прямой ID и отзыв. В общем production-прогоне 6 ноября этот сценарий прошёл; весь private suite — 9/9. Полный pilot M1 не объявляется закрытым.
